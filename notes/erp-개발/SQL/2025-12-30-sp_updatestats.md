# sp_updatestats

sp_updatestats는 SQL Server 데이터베이스 내의 모든 사용자 테이블 및 내부 테이블에 대해 **통계(Statistics)를 한 번에 업데이트**해 주는 아주 유용한 시스템 저장 프로시저입니다.

단순히 모든 것을 업데이트하는 것이 아니라, 나름의 "지능적인" 로직을 가지고 작동합니다. 상세한 작동 방식과 특징은 다음과 같습니다.

 

**1. 주요 작동 원리: "필요한 것만 한다"**

sp_updatestats가 실행되면 데이터베이스의 모든 테이블을 순회하며 다음 과정을 거칩니다.

- **수정 여부 확인:** 테이블의 데이터가 변경되었는지를 나타내는 rowmodctr(행 수정 카운터)를 확인합니다.

- **선별적 업데이트:** 마지막 통계 업데이트 이후에 **최소 1건 이상의 데이터 변경**이 발생한 경우에만 업데이트를 수행합니다.

- **인덱스 및 열 통계 포함:** 인덱스에 연결된 통계뿐만 아니라, 쿼리 최적화 프로그램이 자동으로 생성한 열(Column) 단위 통계도 모두 대상에 포함됩니다.

**2. 구문 사용법**

매개변수 없이 실행하는 것이 일반적이지만, SQL Server 2014(12.x) 버전부터는 resample 옵션이 추가되었습니다.

SQL

 

-- 가장 일반적인 실행 방식\
EXEC sp_updatestats;

-- 이전의 샘플링 비율을 그대로 유지하며 업데이트 (SQL 2014 이상)\
EXEC sp_updatestats @resample = 'resample';

 

**3. UPDATE STATISTICS와의 차이점**

| **비교 항목** | **sp_updatestats** | **UPDATE STATISTICS** |
|----|----|----|
| **범위** | 데이터베이스 내 **전체 테이블** | **특정 테이블** 또는 인덱스 |
| **효율성** | 변경 사항이 있는 것만 골라 수행 | 명령한 대상은 무조건 수행 |
| **정밀도** | 기본 샘플링 비율로 수행 | FULLSCAN 등 정밀도 조절 가능 |
| **사용 목적** | 일괄적인 유지보수 | 특정 쿼리 성능 저하 시 즉각 처방 |

 

**4. 주의사항 및 한계점**

- **기본 샘플링 사용:** sp_updatestats는 기본적으로 FULLSCAN이 아닌 **기본 샘플링(Default Sampling)** 비율을 사용합니다. 만약 데이터 분포가 매우 불균형하여 정밀한 통계가 필요한 대형 테이블의 경우, 이 프로시저 실행 후에도 성능이 개선되지 않을 수 있습니다. (이런 경우엔 해당 테이블만 별도로 WITH FULLSCAN을 써야 합니다.)

- **리소스 소모:** 변경된 테이블이 아주 많을 경우 실행 중에 CPU와 I/O 리소스를 상당히 점유할 수 있습니다. 서비스 사용자가 적은 시간대에 실행하는 것이 권장됩니다.

- **실행 계획 재컴파일:** 통계가 업데이트되면 해당 테이블을 사용하는 기존 쿼리들의 실행 계획이 무효화되고 다음 실행 시 \*\*재컴파일(Recompile)\*\*됩니다. 이는 단기적으로 CPU 부하를 약간 높일 수 있지만, 최적의 경로를 찾기 위한 필수 과정입니다.

 

**5. 권장 활용 시나리오**

1.  **대량 데이터 로드 후:** 대량의 데이터를 INSERT하거나 BULK INSERT한 직후.

2.  **정기 점검 스케줄:** SQL Server Agent를 통해 주 1회 또는 일 1회(야간) 정기적으로 실행.

3.  **성능 저하 발생 시:** 전반적으로 쿼리 속도가 느려졌다고 판단될 때 가장 먼저 시도해 볼 수 있는 조치.

>  

현재 관리하시는 데이터베이스의 규모가 어느 정도인가요? 만약 수 테라바이트(TB) 급의 대용량 DB라면 sp_updatestats 보다는 주요 테이블 위주로 관리하는 것이 더 효율적일 수 있습니다. 필요하시다면 **특정 테이블만 정밀하게 모니터링하는 방법**도 알려드릴 수 있습니다.
