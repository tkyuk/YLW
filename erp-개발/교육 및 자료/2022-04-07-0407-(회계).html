0407 (회계)

MES - 생산에 쓰이는 생산 시스템

ERP - 결국 회계가 핵심

물류의 모든 입고, 출고도 마찬가지

거래를 기록하는게 회계다

돈이 오고 가거나, 물건을 납품하는 등 모든 기록을 회계에 기록

  • 원인과 결과가 일치해야한다 (물건 줬는데 돈을 못받는다? => X
  • 차변, 대변 => 원인과 결과라고 보면 된다

=> 차변금액, 대변금액 일치해야함

자산, 부채, 자본, 손익, 비용

  • 자산 10억, 부채 5억 => 자본(금) 5억

  • 수익 \<-> 비용

거래의 8요소

차변 - 자산의 증가 / 부채의 감소 / 자본의 감소 / 비용의 발생

대변 - 자산의 감소 / 부채의 증가 / 자본의 증가 / 수익의 발생

선이 많지만 직계 되어 있는게 제일 많음

기업회계 기준 일 때 재무제표 종류

포괄손익계산서 => 수익, 비용으로 만듬 (얼마를 쓴지, 얻었는지 / 순이익을 봄) (일정기간 동안의 경영성과)

재무상태표 => 현재 회사의 상태를 보는것 (위의 거래 8요소 사용) ( 일정시점의 재무상태 )

현금흐름표 => 거의 안씀 / 어떤 현금에 대한 거래인지 계속 확인해줘야함

=> GNI에서는 거의 못 했음 => 지금은 좀 늘긴했지만 그래도 별로 안씀

(현금 유입과 현금 유출에 대한 정보)

자본변동표 => 일정시점의 자본의 크기와 일정기간 동안의 자본의 변동에 관한 정보

=============================================================================

  • 시스템 (기본정보 위주)

  • 계정과목 - 회계 등록할 때 사용되는 단위

\<자산, 부채, 자본, 매출과 원가 (수익과 비용), 판매비와 관리비 (비용),

영업외손익 (ex. 임대료), 법인세비용, 기타포괄손익>

환율 1200원 => 1200만원 예상 => 환율 떨어져서 1100만원받음 => 영업외 손익

법인세비용 - 회사에서 나라에 세금 내는 것 (회계사에서 돈 나오면 입력만 해주는 느낌)

기본적인 틀은 비슷하지만 업체마다 다 다름

재무재표는 계정과목만

관리하기 편하게 관리항목이 별도로 있음

금액0 허용여부 = 부가세에서만 사용

귀속부서 - 같이 밥먹음 / 컨설팅 1만원 + 개발팀 2만원 => (개발팀이 더 썼네) 이런걸 알 수 있다

재무회계는 원화만 쓰기 때문에 외화금액이 필요가 없음

회계는 원인과 결과이기 때문에 맞춰줘야함

ex. 외화통장이 있는 경우 => 외화금액 필수여부 체크

  • 결산대체

회계는 계속해서 거래가 일어나는 것이기 때문에 '시점'이 중요

정해진 시점에 사용 => ex. 외화평가

결산을 하기 위해서 강제적으로 조정작업을 한 것 => 외화에 대한 금액은 그대로여야함

==> 결산이 끝나면 원래대로 되돌림 ==> 환원처리

물건 만들거나 할 때 나오는 원가 = 제조우너가

물건을 팔기 위해서 쓰는 비용 (접대비용, 광고) => 판매비

=> 보통 계정을 다 쪼개놓음 (접대 얼마썼는지, 광고에는 얼마 썼는지)

BS계정 : 재무상태표의 계정틀 (관1 항1 목1 절2 세2)

PL계정 :

=> 권장 사항이지 필수는 아니다

  • 전표입력

어떤 작업이 일어났을 때 거래를 입력

차변, 대변 일치해야함 (차대가 있으면 문제가 있을 수 있다)

(원래는 차대를 허용하면 안되지만 / 여러개 입력하다가 사용자가 실수 할 수 도 있기 때문에

중간중간 저장이 가능하도록 차대를 허용하긴하지만 / 결과는 없어야함)

전표는 무조건 증빙이 필요 (EX. 영수증)

전표입력은 일시적인 데이터 => '승인처리' 한 상태여야만 회계에 반영

=> 승인처리 하기전에는 회사의 재무재표에 전혀 영향이 없다

  • 장부

'총계정원장' 많이 본다

관리 항목의 세부정보를 보고 싶다 => 관리항목원장

=> 원장상세조회 => 전표입력

=> 연결고리로 연결되어 있다

  • 건별반제 => 디테일하다

계정과목단위가 아니라

외상매출금 기준으로 얼마 받을거다 => 끝 ==> 계정별로 관리

우리가 외상매출금에서 1월달에 발생했던 금액, 2월은 얼마 등 => 건별반제

건별반제 관리는 어렵다 (어느정도 레벨이 되야 사용)

  • 고정자산

컴퓨터 파는 회사 => 컴퓨터 = 재고자산 \<-> 고정자산

노트북을 바로삼 => 전부 돈내면 손실이 큼 => 집기비품(자산등록)해서 조금씩 비용처리

'내용연수' => 컴퓨터의 내용연수 5년 일경우 => 5년동안 청구가 가능 => 5년이 지나면 불가

  • 상각처리 => 비용 청구
  • IFRS - 국제 회계 기준 (작은 회사는 안쓰고 / 상장한 회사는 필수로 사용 (기준 못 맞추면 상장 못 함)
  • 회계시스템 이외의 영업, 구매, 생산 등 여러개가 있는데

영업의 경우 사고 파는 거래가 계속 나옴 => 회계에 등록해야함

자동으로 전표처리가 가능

세금계산서 조회 => (점프) 세금계산서발행 => 전표처리

=> 자동전표환경설정 에서 '전표 행' 별로 수정이 가능

항목별로 어떤걸 가져올건지, 차변인지 대변인지 등 자유롭게 설정이 가능하다

세금 계산서의 경우 전체가 넘어가기 때문에 체크가 필요 없지만

체크가 필요한 경우도 있다 (EX. 구매)

  • 품목자산분류 설정에 있는대로 전표처리가 이뤄진다

EX. 판매가 일어날 때 => 내수매출계정에 써 있는 값 사용
